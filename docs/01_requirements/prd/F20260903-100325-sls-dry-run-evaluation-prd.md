# PRD：SLS 查询计划与触发评测

## 1. 背景与目标

SLS 聚合或宽范围查询需要先让操作者核对范围，而既有说明不能由命令直接验证；触发场景也只有静态 JSON，缺少对外部运行结果的确定性判定。

目标是在不读取私有配置、凭据或访问 SLS 的情况下输出可复核的查询计划，并让外部 Agent 运行器的 JSONL 结果可重复判定。

## 2. 功能需求

| 编号 | 需求 | 验收标准 |
|---|---|---|
| FR-01 | SLS dry-run | `--dry-run` 输出 profile、查询、时间范围、日志库和限制，且不加载配置或凭据、不访问 API。 |
| FR-02 | 固定计划格式 | 时间范围使用 Unix 秒及 `duration_seconds`，状态固定为 `dry_run`。 |
| FR-03 | 外部结果判定 | JSONL 的 action/route 与 `evals/triggers.json` 对照；缺失、重复或未知用例均失败。 |

## 3. 非功能需求

- 不新增依赖，不改变真实查询路径。
- 不把私有配置、凭据或任何公司信息写入仓库。
- 计划阶段不产生外部副作用。

## 4. 范围与约束

不实现或调用 Agent 模型运行器；运行器由外部环境提供，本项目只维护公开场景和确定性判定器。

## 自审记录

- 需求与验收可由单元测试和本地命令验证。
- 不涉及生产 SLS 调用。
