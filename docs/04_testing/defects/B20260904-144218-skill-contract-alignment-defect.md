# Skill 契约与运行入口不一致缺陷记录

## 根因分析

Skill 要求数据库验证与导出提供用途，但两个 CLI 未声明该参数；配置模板又暗示在仓库内复制文件，而运行时只读取用户私有配置。依赖锁定虽已存在，却没有仓库内的干净环境持续验证。PaaS 请求字段可配置但响应包络固定，说明不足会使使用者误判其通用性。

## 影响范围

- 直接运行 CLI 时无法强制用途声明，执行记录不完整。
- 首次配置可能写入运行时不会读取的位置。
- 依赖更新后的安装回归不能由持续验证及时发现。
- 非固定 PaaS 响应结构只能在运行时失败。

## 修复方案

- 为查询和导出 CLI 增加非空必填 `--purpose`，并在本地受控结果中回显。
- 更正模板目标路径，明确固定 PaaS 响应包络和 macOS/Unix 支持范围。
- 新增只读权限 GitHub Actions，在 macOS 干净环境安装锁定依赖、检查依赖、运行测试和编译脚本。

## 回归测试与验证

- 红灯：缺少 `--purpose`、错误模板路径和缺失 CI 工作流时，新增三项测试失败。
- 绿灯：126 项测试通过，脚本编译通过。
- 干净环境：临时 Python 3.14/macOS 虚拟环境从 `requirements.lock` 安装后，依赖检查、126 项测试和编译均通过。
- 外部 Agent JSONL 评测以及真实 SLS/PaaS 只读集成仍依赖授权的私有运行器和凭据；本次未伪造或执行此类结果。
