# SQL 安全与就绪检查缺陷记录

## 根因分析

共享 SQL 预处理器把任意 `--` 视为行注释，并剥离 MySQL 可执行注释。结果使带算术双减号的多语句 SQL，或带 `/*!...*/` 的锁定/副作用 SQL，能够绕过只读、导出和工单预检。数据库就绪检查未读取测试库密码；评测器默认每条 JSONL 结果都是对象；Excel 直接写目标文件且未兜底校验服务端返回的行数和行结构。

## 修复方案

- 在共享 SQL 预处理器中仅将 `--` 后接 ASCII 空白或控制字符视为注释，并拒绝可执行注释；工单拆分沿用同一 MySQL 注释规则。
- 复用 profile 感知的测试库密码读取函数，让 `setup.py --check --capability db` 在配置完整后校验密码。
- 对评测结果对象作显式验证；对导出结果校验上限和表格行结构，并使用同目录临时 XLSX 原子替换目标。

## 回归测试

- 红灯：9 个边界断言覆盖 ASCII/Unicode 双减号多语句、可执行注释、超限/畸形导出结果、缺失测试库密码和非对象评测行。
- 绿灯：全量 Python 单元测试 97 项通过；Python 编译、Shell 语法与 diff 空白检查通过。
- 未调用 SLS、PaaS、数据库或工单外部接口。
